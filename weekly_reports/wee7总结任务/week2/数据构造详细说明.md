# Week 2 数据构造详细说明：从 ESC-50 到 2-mix 训练样本

这份文档用尽量直白的方式解释 Week 2 到底做了什么。可以把它理解为：

> 我们先从 ESC-50 里挑出一些比较“干净”的单一声音，再把两个声音按可控方式混在一起，最后得到可以用于音频分离训练的样本。

---

## 0. 最终我们想要什么？

音频分离任务里，模型看到的是一个混合音频：

```text
mixture = 声音 A + 声音 B
```

模型要学会在给定目标条件时，把其中一个声音分出来。

例如：

```text
mixture: 狗叫 + 雨声
target condition: dog barking
target: 狗叫
residual: 雨声
```

同一个 mixture 还可以反过来用一次：

```text
mixture: 狗叫 + 雨声
target condition: rain sound
target: 雨声
residual: 狗叫
```

所以每个 2-mix mixture 会生成两条训练记录。

---

## 1. ESC-50 数据集是什么？

ESC-50 是一个环境声音分类数据集。

它的结构大致是：

```text
ESC-50
├── audio/
│   ├── 1-100032-A-0.wav
│   ├── ...
│   └── 5-263902-A-36.wav
└── meta/
    └── esc50.csv
```

基本信息：

| 项目 | 含义 |
|---|---|
| 音频总数 | 2000 条 |
| 类别数 | 50 类 |
| 每类数量 | 40 条 |
| 单条长度 | 5 秒 |
| 原始采样率 | 44.1 kHz |
| 原始声道 | mono |
| 官方划分 | 5 个 fold |

`meta/esc50.csv` 里有几列很重要：

| 字段 | 含义 |
|---|---|
| `filename` | 音频文件名 |
| `fold` | 该音频属于第几折，取值 1 到 5 |
| `target` | 类别数字编号 |
| `category` | 类别名称，比如 `dog`、`rain` |
| `src_file` | 原始来源文件 |
| `take` | 同一来源下的片段标记 |

---

## 2. fold 是什么？split 又是什么？

### 2.1 fold 是 ESC-50 官方给出的折号

ESC-50 官方已经把 2000 条音频分成了 5 个 fold：

```text
fold 1
fold 2
fold 3
fold 4
fold 5
```

每个 fold 有 400 条音频。

更重要的是：ESC-50 在设计 fold 时，会尽量保证来自同一个原始 Freesound 文件的片段不会分散到不同 fold 里。这样做是为了减少数据泄漏。

### 2.2 split 是我们训练时用的数据划分

深度学习训练一般分成三份：

| split | 用途 |
---|---|
| train | 训练模型参数 |
| val | 训练过程中观察效果、调参 |
| test | 最后做最终评估 |

我们使用 ESC-50 官方 fold 构造 split：

```text
fold 1, 2, 3 -> train
fold 4       -> val
fold 5       -> test
```

也就是：

| split | 使用 fold | clean source 数量 |
|---|---:|---:|
| train | 1, 2, 3 | 240 |
| val | 4 | 80 |
| test | 5 | 80 |

这里为什么是 240 / 80 / 80？

因为我们选了 10 个类别，每个类别在每个 fold 里有 8 条音频。

```text
train: 10 类 × 3 个 fold × 每类每 fold 8 条 = 240 条
val:   10 类 × 1 个 fold × 每类每 fold 8 条 = 80 条
test:  10 类 × 1 个 fold × 每类每 fold 8 条 = 80 条
```

这样做的核心目的：

> train、val、test 不共享原始 source，避免模型在测试时“见过”相似片段。

---

## 3. 为什么只选 10 类？

ESC-50 有 50 类，但不是每一类都适合做音频分离。

我们优先选择：

1. 声音事件比较单一；
2. 目标声音比较清楚；
3. 和其他类别混合后仍然可以听出两个来源；
4. 不太像复杂场景声。

最终选了 10 类：

| 类别 | 中文理解 |
|---|---|
| `dog` | 狗叫 |
| `rain` | 雨声 |
| `chirping_birds` | 鸟鸣 |
| `keyboard_typing` | 键盘声 |
| `door_wood_knock` | 敲门声 |
| `clock_tick` | 钟表滴答 |
| `glass_breaking` | 玻璃破碎 |
| `vacuum_cleaner` | 吸尘器 |
| `siren` | 警笛 |
| `car_horn` | 汽车喇叭 |

注意：文档里有时会写 `door_knock`，但 ESC-50 metadata 里的正式类别名是：

```text
door_wood_knock
```

所以代码和 manifest 里统一使用 `door_wood_knock`。

## 4. 音频预处理：RMS、mono、采样率都是什么意思？

在把两个声音混在一起之前，要先把所有 source 处理成统一格式。

我们把每条 clean source 统一成：

```text
sample_rate = 16000 Hz
channels = mono
duration = 5.0 s
rms_target = 0.1
peak <= 0.99
```

### 4.1 sample rate 是什么？

采样率表示一秒钟音频有多少个采样点。

比如：

```text
44.1 kHz = 每秒 44100 个点
16 kHz   = 每秒 16000 个点
```

ESC-50 原始音频是 44.1 kHz。我们统一重采样到 16 kHz。

原因：

1. 课程项目不需要太高采样率；
2. 16 kHz 可以明显减少后续 STFT 和模型计算量；
3. 所有音频长度会统一成：

```text
16000 × 5 = 80000 个采样点
```

### 4.2 mono 是什么？

mono 指单声道。

常见音频有两种：

```text
mono:   一个声道
stereo: 两个声道，左声道 + 右声道
```

如果是 stereo，模型输入会多一个声道维度，处理更麻烦。我们当前任务只关注“有哪些声音”，不研究空间方向，所以统一成 mono。

如果读到多声道音频，可以简单平均：

```text
mono = (left + right) / 2
```

ESC-50 原始数据本身基本就是 mono，但脚本仍然会强制检查和统一，保证流程稳定。

### 4.3 RMS 是什么？

RMS 全称是 Root Mean Square，中文常叫“均方根”。

对一段音频波形 `x`，RMS 定义为：

```text
RMS = sqrt(mean(x^2))
```

直观理解：

> RMS 可以粗略表示一段音频整体有多响，或者能量有多大。

举个简单例子：

```text
RMS 大：整体声音更响
RMS 小：整体声音更安静
RMS 接近 0：可能几乎是静音
```

### 4.4 为什么要做 RMS 归一化？

如果不归一化，某些原始音频可能非常响，另一些非常小。

那混合时就会出现：

```text
声音 A 太大，声音 B 几乎听不见
```

这样模型学到的不是分离，而是被音量差干扰。

所以我们先把每条 source 的 RMS 调到同一个目标值：

```text
rms_target = 0.1
```

公式是：

```text
audio_normalized = audio × (0.1 / RMS(audio))
```

为了避免除以 0，代码里会用一个很小的 epsilon 做保护。

### 4.5 静音过滤是什么？

如果一条音频 RMS 太小，说明它可能几乎没声音。

我们设置：

```text
silence_rms_threshold = 0.0005
```

如果：

```text
RMS(audio) < 0.0005
```

就跳过这条 source。

本次选出的 400 条 source 都通过了检查，没有被过滤掉。

### 4.6 peak 限制是什么？

音频波形通常希望保持在：

```text
[-1, 1]
```

如果超过这个范围，保存 wav 时可能发生 clipping，也就是削波失真。

我们设置：

```text
peak_limit = 0.99
```

也就是：

```text
max(abs(audio)) <= 0.99
```

如果混合后超过 0.99，就把 mixture 和两个 stem 同比例缩小。

## 5. compatibility pair list 是什么？

如果完全随机混合 10 类声音，可能出现一些不太合理的组合。

比如：

```text
clock_tick + siren
```

这不一定错误，但语义上不如“雨声 + 汽车喇叭”自然。

借鉴 HIVE 的思想，我们不做完全随机混合，而是手动指定哪些类别可以混合。

这份允许混合的类别对就叫：

```text
compatibility pair list
```

例如允许：

```text
dog + rain
dog + chirping_birds
rain + chirping_birds
rain + car_horn
rain + siren
keyboard_typing + door_wood_knock
keyboard_typing + clock_tick
keyboard_typing + vacuum_cleaner
door_wood_knock + clock_tick
clock_tick + vacuum_cleaner
glass_breaking + door_wood_knock
glass_breaking + siren
glass_breaking + car_horn
siren + car_horn
```

直观上可以分成几类：

| 场景 | 组合例子 |
|---|---|
| 自然/户外 | dog + rain，rain + birds |
| 城市声音 | siren + car_horn，rain + car_horn |
| 室内声音 | keyboard + clock，keyboard + knock |
| 机械/室内 | vacuum + keyboard，vacuum + clock |
| 突发事件 | glass + knock，glass + siren |

这样做的目的不是说其他组合一定不能出现，而是为了让第一版训练数据更清楚、更可控。

## 6. SNR / 相对增益在 [-5, 5] dB 是什么意思？

### 6.1 先理解 dB

dB 是分贝，是一种表示比例的单位。

在音频振幅上，分贝和倍数的关系是：

```text
gain = 10^(gain_db / 20)
```

例如：

| gain_db | 振幅倍数 gain | 直观理解 |
|---:|---:|---|
| -5 dB | 约 0.562 | 第二个声音变小 |
| 0 dB | 1.000 | 两个声音一样大 |
| +5 dB | 约 1.778 | 第二个声音变大 |

### 6.2 本项目里怎么用？

混合前，两个 source 都已经被 RMS 归一化到 0.1。

然后我们随机采样一个：

```text
gain_db ~ Uniform(-5, 5)
```

再转成倍数：

```text
gain = 10^(gain_db / 20)
```

之后只把第二个 source 乘以这个 gain：

```text
stem_0 = source_A
stem_1 = gain × source_B
```

也就是说：

```text
gain_db < 0: stem_1 比 stem_0 小
gain_db = 0: stem_1 和 stem_0 差不多大
gain_db > 0: stem_1 比 stem_0 大
```

### 6.3 这和 SNR 是什么关系？

SNR 是 Signal-to-Noise Ratio，信噪比。

在分离任务里，可以把：

```text
target 看作 signal
另一个干扰声源看作 noise
```

因为我们先把两个 source 的 RMS 都归一化到 0.1，所以给第二个 source 加一个 `gain_db`，本质上就是在控制两个声音之间的相对响度。

严格说，本项目记录的是：

```text
relative_gain_db
```

它可以近似理解为两个声源之间的 SNR 难度控制。

如果 `gain_db = +5`，第二个 stem 更响；如果当前 target 是第一个 stem，那么任务会更难一些。

## 7. 2-mix 合成规则到底是什么？

现在按时间顺序讲一次。

### 第一步：在某个 split 内选一个兼容类别对

例如当前在 train split。

先从 compatibility pair list 中随机选一个允许组合：

```text
dog + rain
```

只允许从 train 的 clean source 里选，不能拿 val/test 的 source。

### 第二步：分别抽一条 source

例如：

```text
source_A = train 中某一条 dog 音频
source_B = train 中某一条 rain 音频
```

### 第三步：给第二个 source 加随机相对增益

采样：

```text
gain_db = -2.7
```

转成倍数：

```text
gain = 10^(-2.7 / 20)
```

得到：

```text
stem_0 = source_A
stem_1 = gain × source_B
```

### 第四步：相加得到 mixture

```text
mixture = stem_0 + stem_1
```

这就是 2-mix。

### 第五步：防止削波

检查三段音频的最大绝对值：

```text
max_peak = max(
    max(abs(mixture)),
    max(abs(stem_0)),
    max(abs(stem_1))
)
```

如果：

```text
max_peak > 0.99
```

就计算缩放系数：

```text
scale = 0.99 / max_peak
```

然后同比例缩放：

```text
mixture = mixture × scale
stem_0 = stem_0 × scale
stem_1 = stem_1 × scale
```

注意，这里必须三者同比例缩放。

原因是我们要保持：

```text
mixture ≈ stem_0 + stem_1
```

如果只缩放 mixture，不缩放 stem，就破坏了可加性。

### 第六步：保存 wav 文件

每个 mixture 保存成一个文件夹：

```text
rendered_mixtures/train/mix_000001/
  mixture.wav
  stem_0.wav
  stem_1.wav
```

### 第七步：写 manifest

同一个 mixture 写两条记录：

```text
sample 1:
  mixture = mixture.wav
  target = stem_0.wav
  residual = stem_1.wav

sample 2:
  mixture = mixture.wav
  target = stem_1.wav
  residual = stem_0.wav
```

这样一个 2-mix 可以训练两个目标方向。

## 8. SAM Audio 的训练格式是什么？

SAM Audio 可以处理很复杂的提示，比如文本、视觉、时间段等。

但从训练样本的核心结构看，可以抽象成：

```text
(xmix, xtgt, xres, c)
```

含义是：

| 符号 | 含义 |
|---|---|
| `xmix` | mixture，混合音频 |
| `xtgt` | target，当前要分离出来的目标声源 |
| `xres` | residual，除了目标以外的剩余声源 |
| `c` | condition，告诉模型“现在要分离什么” |

例如：

```text
xmix = 狗叫 + 雨声
xtgt = 狗叫
xres = 雨声
c = "dog barking"
```

反过来还可以有：

```text
xmix = 狗叫 + 雨声
xtgt = 雨声
xres = 狗叫
c = "rain sound"
```

## 9. 我们如何和 SAM Audio 对齐？

我们的 manifest 每条记录包含这些字段：

| SAM Audio 抽象字段 | 我们的 manifest 字段 | 含义 |
|---|---|---|
| `xmix` | `mixture_path` | 混合音频路径 |
| `xtgt` | `target_path` | 当前目标 stem 路径 |
| `xres` | `residual_path` | 剩余 stem 路径 |
| `c` | `target_label` / `target_prompt` | 类别条件或文本提示 |

举一个简化后的 manifest 例子：

```json
{
  "sample_id": "train_000001_t0",
  "mix_id": "train_000001",
  "mixture_path": "rendered_mixtures/train/mix_000001/mixture.wav",
  "target_path": "rendered_mixtures/train/mix_000001/stem_0.wav",
  "residual_path": "rendered_mixtures/train/mix_000001/stem_1.wav",
  "target_label": "dog",
  "target_prompt": "dog barking",
  "source_labels": ["dog", "rain"],
  "gain_db": [0.0, -2.7],
  "sample_rate": 16000,
  "duration": 5.0,
  "split": "train",
  "seed": 12345
}
```

## 10. 为什么要和 SAM Audio 对齐？

不是因为我们要复现完整 SAM Audio。

完整 SAM Audio 很大，包含复杂的多模态提示、VAE latent、大规模 DiT 和海量数据。这些都不适合课程项目第一阶段。

我们对齐的是它最核心的数据组织思想：

```text
混合物 + 目标源 + 剩余源 + 目标条件
```

这样做有三个好处。

### 好处 1：任务定义清楚

每条样本都明确告诉模型：

```text
输入是什么？
要分离什么？
剩下的是什么？
条件是什么？
```

这比只保存一个 mixture 文件清楚很多。

### 好处 2：方便下周写 Dataset

下周 PyTorch Dataset 可以直接读 manifest：

```python
{
    "mixture_audio": ...,
    "target_audio": ...,
    "residual_audio": ...,
    "target_label": ...,
    "target_prompt": ...,
}
```

然后动态计算 STFT：

```python
mixture_logmag = log1p(abs(STFT(mixture_audio)))
target_logmag = log1p(abs(STFT(target_audio)))
```

### 好处 3：后续可以自然扩展

现在我们的 condition 很简单：

```text
target_label 或 target_prompt
```

以后如果要扩展，可以换成：

```text
文本 embedding
音频类别 embedding
更复杂的 prompt
```

manifest 格式不用大改。

## 11. 按时间顺序：本周数据构造全过程

下面是从头到尾的完整流程。

### Step 1：读取 ESC-50 metadata

读取：

```text
week2/ESC-50-master/meta/esc50.csv
```

确认：

```text
总数 2000
50 类
每类 40 条
5 个 fold
```

### Step 2：选择 10 个类别

只保留：

```text
dog
rain
chirping_birds
keyboard_typing
door_wood_knock
clock_tick
glass_breaking
vacuum_cleaner
siren
car_horn
```

得到：

```text
10 类 × 每类 40 条 = 400 条 source
```

### Step 3：按 fold 构造 split

```text
fold 1, 2, 3 -> train
fold 4       -> val
fold 5       -> test
```

得到：

```text
train: 240 条 clean source
val:    80 条 clean source
test:   80 条 clean source
```

### Step 4：预处理 clean source

对每条 source：

```text
读取 wav
转 mono
重采样到 16 kHz
保持 5 秒
检查 RMS 是否太小
归一化到 RMS = 0.1
检查 peak 是否超过 0.99
保存 clean source
```

输出：

```text
clean_sources/train/
clean_sources/val/
clean_sources/test/
```

### Step 5：建立 compatibility pair list

人工指定哪些类别可以混合。

例如：

```text
dog + rain
keyboard_typing + clock_tick
siren + car_horn
```

并保存：

```text
metadata/compatibility_matrix.csv
metadata/compatibility_pairs.csv
```

### Step 6：生成 2-mix mixture

对每个 split 单独生成。

目标数量：

```text
train: 10000 mixtures
val:    1000 mixtures
test:   1000 mixtures
```

每个 mixture：

```text
选一个允许的类别对
从当前 split 中抽 source_A 和 source_B
给 source_B 加 [-5, 5] dB 随机增益
相加得到 mixture
防止削波
保存 mixture.wav, stem_0.wav, stem_1.wav
```

### Step 7：生成 manifest

每个 mixture 生成两条记录：

```text
t0: target = stem_0, residual = stem_1
t1: target = stem_1, residual = stem_0
```

所以：

```text
train: 10000 mixtures -> 20000 manifest records
val:    1000 mixtures ->  2000 manifest records
test:   1000 mixtures ->  2000 manifest records
```

### Step 8：验证数据

验证内容包括：

| 检查 | 目的 |
|---|---|
| 数量检查 | 确认 mixture 和 manifest 数量正确 |
| 可加性检查 | 确认 `mixture ≈ stem_0 + stem_1` |
| clipping 检查 | 确认峰值没有超过 0.99 |
| RMS 检查 | 确认响度范围合理 |
| split 检查 | 确认 train/val/test 没有 source 泄漏 |
| compatibility 检查 | 确认所有 mixture 都来自允许类别对 |
| 可视化 | 生成类别统计图和频谱图样例 |

最终验证结果：

```text
additivity check: PASS
clipping check: PASS
shape/sample-rate check: PASS
split leakage check: PASS
compatibility check: PASS
```

## 13. 接下来 Week 3 要做什么？

Week 2 保存的是 waveform，也就是原始波形。

Week 3 会在 Dataset 里读取 manifest，然后动态计算 STFT：

```python
mixture_logmag = log1p(abs(STFT(mixture_audio)))
target_logmag = log1p(abs(STFT(target_audio)))
```

Flow Matching 训练时：

```text
x1 = target_logmag
x0 = Gaussian noise
t ~ Uniform(0, 1)
xt = (1 - t) * x0 + t * x1
v* = x1 - x0
```

模型输入大概是：

```text
xt
t
mixture_logmag
target condition
```

模型输出：

```text
predicted velocity
```

训练目标：

```text
让 predicted velocity 接近 v*
```
